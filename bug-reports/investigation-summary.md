## Rejected candidates

- Import Bus appears to void items when it shrinks an already removed batch to available power (`PartImportBus.importStuff`): rejected because `PartBaseImportBus.doBusWork` first caps the entire tick's `itemToSend` budget to the same energy grid's currently available power before `calculateMaximumAmountToImport` or removal. Without a separate concurrent drain between these calls, the shrink cannot discard part of a legitimate batch.
- ME terminal container appears to lack direct `INJECT`/`EXTRACT` permission checks: rejected because terminal monitors are the grid's `NetworkInventoryHandler`, which checks the `PlayerSource` against `SecurityPermissions.INJECT` and `SecurityPermissions.EXTRACT` before any storage mutation. The container's action source is a `PlayerSource` for the interacting player.
- Crafting CPU appears to overwrite earlier substitute variants when one pattern slot is fulfilled from multiple partial stacks (`CraftingCPUCluster.getExtractItems` / `executeCrafting`): rejected for built-in AE2 gameplay because crafting-mode Pattern Terminal inputs are forced to stack size 1, `PatternHelper` decodes those slots directly, and every AE2 pattern-multiplier action explicitly excludes craftable patterns. A size-one ingredient cannot produce multiple nonempty partial substitutions, so the overwrite state is not reachable from a legitimate AE2 crafting pattern.
- Interface appears to lose unaccepted processing inputs after partially filling an adjacent inventory: rejected because `DualityInterface.pushPattern` retains every leftover in `waitingToSend`, saves and restores that list through world NBT, retries it while ticking, and includes it in both part and block drops if the player breaks the Interface.
- Fluid terminal bulk fill/drain appears to lose partially powered amounts: rejected after tracing the current HEAD change. `Platform.poweredInsert`/`poweredExtraction` cap the modulated transfer to available power; `ContainerMEMonitorable` refills a partially drained container or fills a container with the exact extracted amount, then reinserts/returns any unconsumed remainder.
- Wireless Terminal appears to remain usable after leaving range, changing dimension, losing access-point activity, switching the held item, or exhausting terminal energy: rejected because `AEBaseContainer.portableSourceTick` repeatedly calls the wireless GUI object's `rangeCheck`; that path validates the current held item, dimension/range, Wireless Access Point activity, security key/permission, and energy drain, invalidating the container on failure.
- Annihilation Plane break-permission caching appears to allow mining shortly after a cancellation changes: not accepted because the only standalone AE2 check, `World.canMineBlock`, is repeated for the actual break. A player-visible stale Forge `BreakEvent` cancellation requires a particular protection mod/configuration, and no supported built-in AE2-only reproduction was established.
- Grid split/join and path-recursion code appears vulnerable because recursive traversal mutates a shared `depth` with `++depth`: rejected as an ordinary-player finding after tracing callers. The affected `FIND_ITEMS` path has a default budget of 100, and a visible failure would require an unusually large, branching subnetwork layout; no concrete high-impact supported reproduction was established. Normal grid split detection uses dedicated visited/result sets.
- Grid profiling can divide by zero when stopped before any samples: rejected because the entry point is the permission-level-2 administrative `profile` command, outside ordinary-player gameplay.
- Spatial transition capture appears able to lose blocks when a movable-handler callback fails: rejected because the transition plane registers the captured representation before movement and `CachedPlane` retains/replays handler-owned state through the recovery path. The remaining exceptional cases require a third-party movable handler to violate its contract.
- Formation and Annihilation Plane partial transfer looked capable of discarding a remainder: rejected after tracing their simulate/modulate sequence and drop/rollback branches; accepted quantities are bounded to actual target/source capacity and unaccepted item ownership is retained or spawned.
- Fluid and RF P2P cycles looked analogous to the accepted item-comparator recursion: rejected because those forwarding implementations carry explicit recursion/visited guards. The item inventory/comparator layer lacks the corresponding guard.
- P2P part-type replacement throws if the replacement cannot be re-added: rejected because normal replacement first verifies compatible type/side state and removes the old part; no supported player action was found that makes the subsequent add fail without an external protection/integration violation.
- IO Port rollback ignores a second insertion remainder, which initially suggested item loss: rejected for built-in transfers because the source is either the same cell that just freed capacity or the same synchronous network monitor that just supplied the stack. No intervening supported mutation can consume the newly freed source capacity inside the transfer call.
- Super ME Replenisher refund mutates entries while iterating and initially appeared able to emit zero-sized packet drops: rejected because `IAEStackList` iterates through `MeaningfulAEStackIterator`, which excludes records reduced to zero. Its buffers are persisted to NBT, and breaking first refunds what the grid accepts then packet-drops every meaningful remainder alongside its cells.
- Advanced Inscriber consumes inputs at job start, which initially suggested loss if output becomes blocked or the block unloads: rejected because the result becomes a dedicated `pendingOutput` before consumption, that buffer and progress are saved to NBT, output insertion waits for complete stack capacity, and breaking explicitly drops a copy of the pending result along with the normal inventory and upgrades.
- Remaining legitimate server packet handlers appeared to trust coordinates or configuration values broadly: rejected as ordinary-client findings after tracing their senders and server gates. Normal actions are constrained by the current concrete container, route new GUIs back through `GuiBridge.securityCheck`, or revalidate the held tool/range; stale protected-container actions are already consolidated in BUG-003. No additional accepted path required only an ordinary packet emitted by the stock client.
